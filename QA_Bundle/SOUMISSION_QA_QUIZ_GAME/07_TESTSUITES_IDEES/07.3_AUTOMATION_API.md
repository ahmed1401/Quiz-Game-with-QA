# 07.3 — Automatisation API (Jest + SuperTest)

## Objectifs
- Cadenasser les endpoints `/api/users/*` et `/api/questions`.
- Détecter rapidement les régressions d'authentification, scoring et catalogue questions.
- Produire un retour CI via `npm test` (backend) en < 60 s.

## Stack & structure
| Composant | Usage |
|-----------|-------|
| Jest 29.x | Runner.
| SuperTest 6.x | Client HTTP.
| mongodb-memory-server 10.x | Base isolée par scénario.

Organisation :
```
backend/
├─ tests/
│  ├─ users.spec.ts
│  ├─ questions.spec.ts
│  └─ setup.ts (init MongoMemoryServer, helpers)
├─ jest.config.js
└─ package.json ("test": "jest --runInBand")
```

## Scénarios essentiels
### `users.spec.ts`
1. `POST /api/users/register` crée un utilisateur (hash bcrypt + scores [0,0,0,0]).
2. Inscription doublon → 400 avec message explicite.
3. `POST /api/users/login` renvoie 200, password absent de la réponse.
4. `PATCH /api/users/score/:id` met à jour uniquement si score supérieur.
5. Même endpoint retourne 400 quand `categoryIndex` ∉ [0,3].
6. `GET /api/users/leaderboard` renvoie liste triée décroissante.

### `questions.spec.ts`
1. `GET /api/questions?category=Computer%20Science` renvoie 10 questions.
2. Paramètre manquant → 400 (bad request).
3. `POST /api/questions` avec catégorie invalide → 400 (enum Mongo).

## Bonnes pratiques
- Utiliser fixtures injectées via Mongoose avant chaque test ; nettoyer après (`afterEach`).
- Centraliser la configuration dans `tests/setup.ts` (démarrage MongoMemoryServer, creation app Express, helpers auth).
- Exporter les rapports JUnit via `jest-junit` si demandés par la CI/CD.

## Critères de réussite
- 100% PASS, temps < 60 s, couverture contrôleurs ciblée ≥ 80%.
- Aucune dépendance à une base distante (tout en mémoire).
