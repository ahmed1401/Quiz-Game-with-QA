# 07.4 — Scénarios Non Fonctionnels

## Performance UI (Lighthouse)
- **KPI** : LCP & TTI < 3 s, score Performance ≥ 85 en profil mobile 4G.
- **Procédure** : `npm run build && npm run preview`, puis `npm run lh:audit:auth` sur les routes login/register/quiz/leaderboard/welcome.
- **Sorties** : HTML/JSON sous `frontend/lighthouse-reports/<timestamp>/`, consolidées dans `04_PERFORMANCE_SÉCURITÉ/04.1_RAPPORT_PERFORMANCE_SÉCURITÉ.pdf`.

## Charge API (k6)
- **Script** : `QA_TestSuites/04_NonFunctional/k6_scenario.js` (50 VUs, palier 0→50→maintien→descente).
- **Commande** : `./tools/k6/k6 run QA_TestSuites/04_NonFunctional/k6_scenario.js`.
- **Attentes** : p95 < 500 ms, erreur < 1 %. Résultats JSON stockés dans `04.2_RÉSULTATS_BRUTS_K6.json`.

## Sécurité passive (OWASP ZAP)
- **But** : Aucune alerte Medium/Critical, headers CSP/X-Frame-Options/X-Content-Type-Options présents.
- **Commandes** :
  - Backend : `java -jar zap-2.16.1.jar -cmd -quickurl http://localhost:5000/api/questions -quickout QA_Bundle/SOUMISSION_QA_QUIZ_GAME/04_PERFORMANCE_SÉCURITÉ/04.3_SCAN_SÉCURITÉ_ZAP_BACKEND.html`.
  - Frontend : même commande vers `http://localhost:4300` → `04.4_SCAN_SÉCURITÉ_ZAP_FRONTEND.html`.

## Accessibilité
- **Outils** : `pa11y` ou `cypress-axe` (backlog).
- **Seuil** : 0 erreur WCAG 2.1 AA sur login/register/quiz.

## Résilience / Recovery
- **Test** : couper MongoDB pendant un quiz ; vérifier qu'un message d'erreur contrôlé apparaît côté UI et que le backend logge l'incident sans crash.
