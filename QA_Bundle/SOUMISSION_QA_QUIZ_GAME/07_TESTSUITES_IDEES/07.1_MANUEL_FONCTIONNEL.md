# 07.1 — Suite Manuelle Fonctionnelle

## Objectif
Valider les parcours critiques du Quiz Game via des scénarios Gherkin priorisés (MoSCoW) avant ou en parallèle des automatisations.

## Pré requis
- Seed Mongo via `cd backend && node addQuestions.js`.
- Démarrer API (`node app.js`) et SPA (`cd frontend && npm start`).
- Comptes de référence : `user_alpha@example.com` / `Password!123`, `user_beta@example.com` / `Password!123`.

## Périmètre couvert
| Domaine | Points de contrôle principaux | Priorité |
|---------|--------------------------------|----------|
| Authentification | Inscription, blocage doublon, login/logout, routes protégées. | Must |
| Quiz | Sélection obligatoire, loader API, mélange réponses, feedback couleurs, navigation linéaire, écran résultats, sauvegarde high score. | Must/Should |
| Leaderboard | Protection AuthGuard, colonnes complètes, tri décroissant, message "No users found". | Must/Could |
| Données & API | Enum catégorie, validation `categoryIndex`, scores initiaux, calcul total UI cohérent. | Must/Should |
| NFR rapides | LCP visuel < 3 s, headers sécurité, navigation clavier. | Should/Could |

## Procédure recommandée
1. Exécuter Auth → Quiz → Leaderboard → Données → NFR dans cet ordre pour maximiser la détection d'impacts régressifs.
2. Consigner chaque résultat dans la feuille de suivi (statut, preuves, éventuelle ouverture de DEF-xxx).
3. Critères de sortie : 100% des Must en PASS, aucun défaut bloquant/majeur ouvert, Should/Could évalués et documentés.
